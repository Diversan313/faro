# Faro

Небольшой Cloudflare Worker, который передаёт запрос к ссылке подписки и при необходимости приводит названия конфигов к аккуратному виду.

Faro не собирает подписки и не хранит их у себя. Он получает ссылку, запрашивает её содержимое и возвращает ответ клиенту.

## Что умеет

- Принимает ссылку подписки прямо в адресе Worker — прописывать её в исходном коде не нужно.
- Передаёт `hwid` источнику подписки. Его можно указать в заголовке `x-hwid`, `hwid` или в параметре URL.
- При наличии `hwid` также передаёт заголовки устройства: `x-device-os`, `x-device-model` и `x-ver-os`.
- Может оставить в названиях конфигов только флаг страны. Если флаг не найден, используется `🌐`.
- Обрабатывает обычные списки ссылок, Base64-подписки, JSON-конфиги и ссылки `vmess://`.
- Не пытается переименовывать слишком большие ответы: если их размер превышает установленный лимит, содержимое возвращается как есть.

## Как подключить

Сначала создайте Worker в Cloudflare:

1. Откройте **Workers & Pages** и выберите **Create** → **Worker**.
2. Вставьте содержимое файла `worker.js`.
3. Нажмите **Deploy** и скопируйте адрес созданного Worker.

После этого можно собирать ссылку на подписку через адрес Worker.

## Как пользоваться

Есть два варианта передачи исходной ссылки.

**Через адресную строку:**

```text
https://YOUR-WORKER.workers.dev/sub=https://example.com/path/to/sub?hwid=YOUR_HWID
```

**Через параметр `sub`:**

```text
https://YOUR-WORKER.workers.dev/?sub=example.com/path/to/sub&hwid=YOUR_HWID
```

Вместо `YOUR-WORKER` укажите поддомен своего Worker, а вместо `example.com/path/to/sub` — адрес подписки. `https://` в значении `sub` можно не писать: Faro добавит его автоматически.

Параметр `hwid` необязателен. Другие параметры запроса, кроме `sub` и `hwid`, передаются дальше источнику подписки.

## Настройка названий

В начале `worker.js` находится переключатель `RENAME`:

```js
const RENAME = 1;
```

- `1` — оставить в названии только первый найденный флаг страны. Если его нет, поставить `🌐`.
- `0` — не менять названия и вернуть содержимое подписки без переименования.

## Несколько важных деталей

- Запрос к источнику отправляется с User-Agent `Happ/1.0.0 (iOS; v2ray)`.
- При ошибке декодирования или разбора JSON/VMess Worker старается вернуть исходный ответ без изменений.
- Ответы не кэшируются (`Cache-Control: no-store`).
- Worker принимает запросы `GET` и `HEAD`. Остальные методы отклоняются.

## Безопасность

Faro не проверяет, кому принадлежит переданная ссылка, и не ограничивает список хостов. Поэтому любой, кто знает адрес Worker, может использовать его со своей ссылкой. Не размещайте адрес публично, если Worker предназначен только для личного использования.

Ссылка подписки и её токен передаются через Cloudflare. При включённом логировании URL и параметры запроса могут попасть в логи платформы. Не добавляйте реальные токены и HWID в публичный репозиторий.
